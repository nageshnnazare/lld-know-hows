## 💡 Interview Tips by Problem Type

### State Management Problems
**Problems**: ATM, Elevator, Traffic Signal, Vending Machine

**Approach**:
1. Identify all possible states
2. Define transitions between states
3. Handle edge cases (invalid transitions)
4. Use State pattern for clean code

**Key Questions to Ask**:
- What are all possible states?
- What triggers state transitions?
- Can states be reverted?
- Are there any invalid transitions?

### Booking/Reservation Problems
**Problems**: Parking, Hotel, Movie, Car Rental, Restaurant

**Approach**:
1. Identify resources to be booked
2. Define availability check mechanism
3. Handle concurrent bookings (locking)
4. Implement cancellation/modification
5. Payment integration

**Key Questions to Ask**:
- How to handle concurrent bookings?
- Overbooking allowed?
- Cancellation policy?
- Payment flow?

### Matching/Assignment Problems
**Problems**: Ride Sharing, Food Delivery, Elevator Assignment

**Approach**:
1. Define matching criteria (distance, rating, etc.)
2. Implement matching algorithm (greedy, optimal)
3. Handle rejections/timeouts
4. Real-time updates

**Key Questions to Ask**:
- Matching criteria priority?
- Real-time or batch processing?
- What if no match found?
- How to handle cancellations?

### Real-time Systems
**Problems**: Stock Trading, Notification, Social Feed

**Approach**:
1. Event-driven architecture
2. Observer pattern for updates
3. Queue for processing
4. Consistency vs Availability tradeoffs

**Key Questions to Ask**:
- Latency requirements?
- Consistency guarantees?
- Scale (users, events)?
- Failure handling?

## 📝 Common Interview Questions

### General Questions (All Problems)

1. **"Walk me through your class diagram"**
   - Start with core entities
   - Explain relationships
   - Justify design decisions

2. **"What design patterns did you use and why?"**
   - Don't force patterns
   - Explain benefits
   - Mention alternatives

3. **"How would you handle concurrency?"**
   - Identify critical sections
   - Use appropriate locks
   - Consider deadlocks

4. **"How would this scale?"**
   - Database sharding
   - Caching strategies
   - Load balancing
   - Microservices

5. **"What would you do differently for millions of users?"**
   - Distributed systems
   - CAP theorem tradeoffs
   - Async processing
   - CDN usage

### Follow-up Deep Dives

**Database Questions**:
- Schema design
- Indexing strategy
- Query optimization
- NoSQL vs SQL choice

**API Design**:
- RESTful endpoints
- Request/Response format
- Authentication
- Rate limiting

**Testing**:
- Unit test strategy
- Integration tests
- Load testing
- Edge cases

**Deployment**:
- CI/CD pipeline
- Monitoring
- Rollback strategy
- A/B testing

## 🎓 How to Practice

### Solo Practice
1. Set a timer (stick to time limits)
2. Start with requirements gathering (ask questions)
3. Draw class diagram on paper/whiteboard
4. Code in your IDE
5. Test with examples
6. Review and refactor

### Mock Interview Practice
1. Have someone give you the problem
2. Think out loud
3. Ask clarifying questions
4. Explain your approach before coding
5. Handle follow-up questions
6. Defend design decisions

### Code Review Practice
1. Review solutions in this repo
2. Identify improvements
3. Compare with your solution
4. Note different approaches
5. Understand tradeoffs

### Problem Selection Flowchart
```
Time Available?
├─ 20-30 min → Easy problems (Logger, URL Shortener)
├─ 30-45 min → Easy-Medium (Parking, ATM, Library)
├─ 45-60 min → Medium (Elevator, Hotel, LRU)

Weak Area?

├─ Design Patterns → ATM, Vending, Elevator
├─ Concurrency → Movie Booking, Elevator
├─ Data Structures → LRU, File System
├─ Algorithms → Ride Share, Stock Trading
└─ System Design → Payment, Notification
```

### Design Pattern Quick Match
```
Need: Multiple formats/types → Factory
Need: Single instance → Singleton
Need: Complex construction → Builder
Need: Runtime behavior change → Strategy
Need: State-dependent behavior → State
Need: Notify multiple objects → Observer
Need: Add features dynamically → Decorator
Need: Tree structure → Composite
Need: Encapsulate requests → Command
```
